# ライセンスの使用状況と容量

>[!AVAILABILITY]
>
>この機能を使用するには、次の権限が必要です。
>
>- **ライセンス使用状況ダッシュボードの表示**
>   - この権限を使用すると、キャパシティホームを&#x200B;**表示**&#x200B;できます。
>- **サンドボックスの管理**
>   - この権限を使用すると、キャパシティの割り当てを&#x200B;**編集**&#x200B;できます。
>   - さらに、**any** サンドボックスの容量を編集するには、**すべてのサンドボックスへのアクセス権を**&#x200B;に割り当てる必要があります。
>
>Experience Platform内の権限について詳しくは、[ アクセス制御の概要](/help/access-control/home.md#permissions)を参照してください
>
>さらに、High Throughput Streaming Segmentationを購入した場合、容量を使用して容量を割り当てることができるのは&#x200B;**not**&#x200B;になります。 お客様のキャパシティを更新するには、Adobe カスタマーケアにお問い合わせください。

Adobe Experience Platformでは、組織がガードレールのいずれかを超えたかどうかをキャパシティで確認し、これらの問題を解決する方法に関する情報を提供します。

Experience Platformのガードレールについて詳しくは、[Real-Time CDP ガードレールの概要](../../rtcdp/guardrails/overview.md)をお読みください。

## 処理能力動作 {#behavior}

>[!CONTEXTUALHELP]
>id="platform_capacity_streamingthroughput"
>title="ストリーミングスループット"
>abstract="ストリーミングスループットの値は、実稼動サンドボックスと開発サンドボックス間で、プロファイルにストリーミング取り込むための1秒あたりのピークインバウンドイベントの組み合わせを測定します。"

>[!CONTEXTUALHELP]
>id="platform_capacity_streamingaudiences"
>title="ストリーミングオーディエンス数"
>abstract="サンドボックスあたりのストリーミングオーディエンスの最大数。この数には、サンドボックス内にあるエッジオーディエンスの数が含まれます。"

>[!CONTEXTUALHELP]
>id="platform_capacity_edgeaudiences"
>title="エッジオーディエンス"
>abstract="サンドボックスあたりのエッジオーディエンスの最大数。"

現在、キャパシティは次のサービスをサポートしています。

- ストリーミングセグメント化
- ストリーミング取り込み
- エッジセグメント化

これらのサービスでは、次のガードレールが追跡されます。

- ストリーミングオーディエンスの最大数は500です
- エッジオーディエンスの最大数は150です
- ストリーミング取り込みの最初の結合スループットは、1500 レコード/秒（rps）です
   - この組み合わされたストリーミングスループットは、実稼動および開発サンドボックスをまたいでリアルタイム顧客プロファイルにストリーミング取り込むために、1秒当たりのピークインバウンドイベントの組み合わせを測定します。
   - 1秒間に最大13,500 レコードのストリーミングセグメンテーションサポートを追加で購入できます。 追加の使用権限の購入について詳しくは、[Real-Time CDPの製品説明](https://helpx.adobe.com/jp/legal/product-descriptions/real-time-customer-data-platform-b2c-edition-prime-and-ultimate-packages.html)を参照してください。
- エッジセグメント化の組み合わせスループットは、1500 レコード/秒（rps）です

オーディエンスのキャパシティは&#x200B;**サンドボックス** レベルです。 つまり、組織内にあるサンドボックスごとに500のストリーミングオーディエンスを設定でき、そのうち150はエッジオーディエンスになる可能性があります。

ストリーミングスループット容量は&#x200B;**組織** レベルで、個々のサンドボックスに配布できます。 例えば、ストリーミング取り込みのスループットが1500 rpsの場合、実稼動サンドボックスを1300 rpsに、開発サンドボックスを200 rpsに設定できます。

Experience Platformでは、15分間のローリング間隔でサンドボックスのスループットが計算されます。 このスループットはリアルタイムで測定され、データは60秒ごとに更新されます。

使用率がライセンス容量の80%と90%に達した場合、Experience Platformはアラートを発行し、指定した容量の上限に達していることを通知します。 設定を変更して、アラートを受信する容量の割合をカスタマイズしたり、アラートを完全に削除したりできます。

使用状況がライセンス容量の100%を超えた場合、容量に違反していると見なされます。 キャパシティに違反した場合は、次の制限が適用されます。

>[!NOTE]
>
>Adobe Journey Optimizerへのアクセス権がある場合、次の制限は&#x200B;**not**&#x200B;が適用されます。

- イベント処理キューが12時間を超える場合、イベントデータ **can**&#x200B;をストリーミングパーソナライゼーションから削除できます
- 削除されたイベントデータは&#x200B;**not**&#x200B;がプロファイルに取り込まれます
   - イベントがいつ削除されたかがわかります
   - イベントは、使用権限に応じて、データレイク内で利用できます
   - 必要に応じて、クエリサービスを使用してデータを直接再取り込みできます。**

### ストリーミング容量 {#streaming-capacities}

「ストリーミング容量」セクションには、組織のストリーミング容量に関する情報の概要が表示されます。 具体的には、このセクションには、ストリーミングスループットとストリーミングオーディエンスに関するキャパシティ情報が表示されます。 サンドボックスごとに、この情報をフィルタリングし、ルックバック期間を変更できます。

#### ストリーミングスループット {#streaming-throughput}

**[!UICONTROL Streaming throughput]** セクションには、組織のサンドボックス内のストリーミングスループットに関する情報が表示されます。 ストリーミングスループット値は、プロファイルにストリーミング取り込むための1秒当たりのピークインバウンドイベントの合計数を測定します。

![処理能力の詳細ページ内のストリーミングスループットセクションが表示されます。](/help/landing/images/capacity/streaming-throughput-section.png)

| 列の名前 | 説明 |
| ----------- | ----------- |
| サンドボックス | サンドボックスの名前。 |
| サービス | サンドボックスで使用されるサービス。 現在、サポートされている値はプロファイルのみです。 |
| 使用状況（ピーク） | 選択したルックバック期間内のサンドボックス内のデータのピークストリーミングスループット。 |
| 処理能力 | サンドボックスの最大ピークストリーミングスループット。 |
| 違反 | 違反が発生した場合、ストリーミングスループットの違反のタイプ。 |
| 推奨されるアクション | 違反を軽減するために推奨されるアクションを説明する列。 |

個々のサンドボックスを選択すると、サンドボックスのストリーミングスループットをより詳細に表示できます。

![ サンドボックスは、ストリーミングスループットセクション内でハイライト表示されます。](/help/landing/images/capacity/select-sandbox.png)

ストリーミングスループットの詳細ページが表示されます。 リクエストのスループットとキャパシティ制限、サンドボックスとそのスループットのリスト、組織のキャパシティを割り当てるボタンが表示されるグラフが表示されます。

![ ストリーミング スループット ページが表示され、選択したサンドボックスのストリーミング スループットに関する詳細情報が表示されます。](/help/landing/images/capacity/streaming-capacity-allocation.png)

組織のストリーミングスループット容量を更新するには、**[!UICONTROL Allocate capacities]**&#x200B;を選択します。

![ ストリーミングスループットの詳細ページで「キャパシティを割り当てる」ボタンが強調表示されます。](/help/landing/images/capacity/select-allocate.png)

配分ページが表示されます。 このページでは、さまざまなサンドボックスのキャパシティを設定できます。 すべてのキャパシティ **の合計は、組織のキャパシティの合計に等しくなければなりません**。

![容量割り当てページが表示されます。](/help/landing/images/capacity/allocate-capacity.png)

>[!NOTE]
>
>新しいキャパシティは、**100**&#x200B;の順序でのみ設定できます。 例えば、サンドボックスの新しい容量の値を300または500に設定できますが、**この値を450に設定することはできません**。
>
>値が100の順序でない場合は、それに応じて切り上げまたは切り捨てられます。

キャパシティの割り当てを更新した後、**[!UICONTROL Save]**&#x200B;を選択して更新を完了します。 変更が組織に反映されるまでに最大10分かかる場合があります。

## ストリーミングスループットのベストプラクティス {#streaming-throughput-suggestions}

次のいずれかの推奨事項を採用することで、スループット違反を解決できます。

1. サンドボックスの割り当て容量を増やします。
2. [監視ダッシュボード ](/help/dataflows/ui/monitor-streaming-profile.md)で高スループットデータフローを特定し、必要に応じてこれらのデータフローに対してスロットルまたはフィルタリングを適用します。
3. バッチ取り込みを使用して、遅延の低いユースケース向けに取り込みを最適化します。

さらに、データフローを見て、データ戦略を最適化できるかどうかを確認することもできます。

| 貢献要因 | 現状 | ユースケースへの影響 | ベストプラクティス |
| --- | --- | --- | --- |
| バッチからストリーミングへの変換 | バッチワークロードをストリーミングに変換すると、スループットが大幅に向上し、パフォーマンスとリソースの割り当てに影響を及ぼす可能性があります。 たとえば、レート制限のないイベントの後にプロファイルの一括更新を実行します。 | 低遅延の処理が必要ない場合、バッチ方式のユースケースではストリーミング戦略は不要です。 | ユースケース要件の評価。 バッチアウトバウンドマーケティングの場合は、ストリーミングの代わりに[ バッチ取り込み](/help/ingestion/batch-ingestion/overview.md)を使用して、データ取り込みをより効率的に管理することを検討してください。 |
| 不必要なデータ取り込み | パーソナライゼーションに必要のないデータを取り込むと、価値を向上させることなくスループットが向上し、リソースを浪費します。 例えば、関連性に関係なくすべての分析トラフィックをプロファイルに取り込むことです。 | 関連性のないデータが多すぎるとノイズが生じ、インパクトのあるデータポイントを特定することが難しくなります。 また、オーディエンスやプロファイルを定義および管理する際に摩擦が生じる可能性もあります。 | ユースケースに必要なデータのみを取り込みます。 不要なデータは除外するようにしてください。<ul><li>**Adobe Analytics**: [行レベルのフィルタリング ](/help/sources/tutorials/ui/create/adobe-applications/analytics.md#filtering-for-real-time-customer-profile)を使用して、データ収集を最適化します。</li><li>**ソース**: [[!DNL Flow Service] APIを使用して、](/help/sources/tutorials/api/filter.md)や[!DNL Snowflake]など、サポートされているソースの行レベルのデータ [!DNL Google BigQuery]をフィルタリングします。</li></li>**Edge データストリーム**: [動的データストリーム ](/help/datastreams/configure-dynamic-datastream.md)を設定して、WebSDKから受信するトラフィックの行レベルのフィルタリングを実行します。</li></ul> |

## Edgeのセグメンテーションスループットのベストプラクティス {#edge-best-practices}

次のいずれかの推奨事項を採用することで、エッジセグメント化スループット違反を解決できます。

1. [監視ダッシュボード ](/help/dataflows/ui/monitor-edge.md)で高スループットデータストリームを特定し、必要に応じてこれらのデータストリームに対してスロットルまたはフィルタリングを適用します。
2. バッチ取り込みを使用して、遅延の低いユースケース向けに取り込みを最適化します。
3. 引き続き問題が発生する場合は、Adobe カスタマーケア担当者にお問い合わせください。

## よくある質問 {#faq}

次のセクションでは、キャパシティの機能に関するよくある質問の概要を説明します。

### 目標の最大スループットを下回る最大スループット制限を設定できますか？

+++ 回答

いいえ。最大結合スループット制限&#x200B;**は、組織のガードレールに合わせて合計**&#x200B;する必要があります。

+++

### 最大容量を超えた場合はどうなりますか？

+++ 回答

これは、どの容量を超えているかによって異なります。

現在、許可されているオーディエンスの最大数を超えると、過剰なオーディエンスは影響を受けません。 ただし、今後、新しいオーディエンスを作成する機能が制限される可能性があります。

ストリーミングスループットを上回ると、取り込みとセグメンテーションにパフォーマンスの遅延が発生します。

+++

### なぜ私は私の最大能力を守るべきですか？

+++ 回答

最大限の容量を使用することで、データの一貫性を維持し、データの整合性を維持できます。

イベントのピーク時には一貫性のあるパフォーマンスを実現し、システムのパフォーマンスに悪影響を与え、下流の顧客体験に影響を与える可能性のある技術的問題を回避することで、データの健全性とシステム全体のパフォーマンスを向上させます。

+++

### ストリーミング取り込みのスループットを管理するためのベストプラクティスを教えてください。

+++ 回答

ストリーミング取り込みのスループットを最大限に管理するには、データセットを評価して、パーソナライゼーションに必要なデータが優先されるようにします。


リアルタイム処理が必要ない場合は、ストリーミング取り込みの代わりにバッチ取り込みを使用します。

+++
