# Real-Time CDP B2B editionへのアーキテクチャのアップグレード

>[!IMPORTANT]
>
>このドキュメントでは、Real-Time CDP B2BおよびB2P Editionsへのアーキテクチャアップグレードの概要を説明します。 アップグレードには、ほとんどの顧客からの操作は必要ありません。 ただし、自動的にアップグレードできないオーディエンスもあります。 Adobeは、これらのシナリオに対処するために直接協力します。 アップグレードがAdobe Experience Platformの既存の機能にどのような影響を与えるかについて詳しくは、このドキュメントを参照してください。 ご不明な点がある場合は、Adobeアカウントチームにお問い合わせください。

Adobeは、B2BおよびB2P Editionsを再設計し、スケーラビリティ、パフォーマンス、信頼性を向上させると同時に、より高度なB2B ユースケースもサポートしています。 Adobeでは、B2BおよびB2Pのあらゆる顧客に対して、これらの改善点をあらゆる顧客に提供できるように、新しいアーキテクチャを導入します。

拡張アーキテクチャは、次のメリットをもたらします。

* **データ取り込みの拡張性**：何千人もの人々に接続されたアカウントなど、基数の高いB2B関係のサポートを強化しました。
* **パフォーマンスが高く信頼性の高いオーディエンス評価**：複雑なB2B オーディエンス向けのセグメンテーションを迅速かつ柔軟に実行します。
* **エンティティ解決**:B2B エンティティのID解決を強化し、データ品質を向上させ、重複を減らし、より正確なセグメンテーションと集計を可能にします。

>[!TIP]
>
>オーディエンスの規模や複雑さによっては、オーディエンスの評価やアクティベーションに必要な時間が若干変更される場合があります。
>
>特に、ビジネスプロセスがセグメンテーションとアクティベーションのタイムリーな完了に依存している場合は、セグメンテーションの実行時間を監視することをお勧めします。 これにより、ワークフローをスムーズに実行し続け、予期しない変更に積極的に対処できるようになります。

## 新機能

アーキテクチャのアップグレードに含まれる主な機能強化については、次を参照してください。

### オーディエンスメンバーシップのアカウントスナップショット

新しいB2B アーキテクチャでは、スナップショット書き出しにアカウントエンティティのオーディエンスメンバーシップの詳細が含まれるようになりました。 この機能を使用すると、アカウントレベルのオーディエンスステータス、タイムスタンプ、メンバーシップ指標にアクセスできます。

このアップグレードにより、次のことが可能になります。

* マーケティングチームと運用チームが、アカウントオーディエンスのメンバーシップを直接検証できるようにします。
* プロファイル（人物）モデルとアカウントセグメンテーションモデルの間の機能パリティを実現し、エンティティ間で一貫したエクスペリエンスを実現します。

詳しくは、[ アカウントオーディエンス ](../segmentation/types/account-audiences.md)に関するドキュメントを参照してください。

### B2B エンティティを含むオーディエンス向けのオーディエンスサイズ

B2B エンティティを持つオーディエンスのオーディエンスサイズの推定値が、正確な精度で計算されるようになりました。 これらの見積もりは、プレビュー中に入手でき、複雑なB2B関係を含むオーディエンスに、より正確で信頼性の高いインサイトを提供します。

このアップグレードにより、次のことが可能になります。

* 正確なオーディエンス数推定からインサイトを得て、オーディエンス作成プロセスにおける計画と意思決定を改善できます。
* 複雑なB2B オーディエンスを、より正確なオーディエンス見積もりを把握した上で、自信を持って設計。
* よりスマートなキャンペーン計画、より正確なターゲティング、より優れたリソース割り当てが可能になります。

詳しくは、[ アカウントオーディエンス ](../segmentation/types/account-audiences.md)に関するドキュメントを参照してください。

## 既存の機能へのアップグレード

B2B アーキテクチャのアップグレードの一環として、次の機能が更新されました。

### B2B属性とエクスペリエンスイベントを使用したマルチエンティティオーディエンスの更新

新しいアーキテクチャのアップグレードの一環として、エクスペリエンスイベントフィルターは、B2B属性を含む単一のマルチエンティティオーディエンス内で使用できなくなりました。

同じオーディエンスロジックを実現するには、セグメントビルダーを使用して[ オーディエンスを追加し、オーディエンスを参照](../segmentation/ui/segment-builder.md#adding-audiences)できます

例：

* Experience Event オーディエンスの作成
   * 行動条件を個別に定義します。 例：「過去3日間に価格ページを訪問した人物」
* B2B属性を使用して、マルチエンティティオーディエンスを作成します。
   * ここから、エクスペリエンスイベントのオーディエンスを、このオーディエンスの基準の一部として参照できます。 例：「アカウントが&#x200B;**&#39;Finance&#39;**&#x200B;業界にある商談の&#x200B;**&#39;意思決定者&#39;**&#x200B;である人物と、過去3日間に価格ページを訪問した人物のメンバー。

アップグレードが完了したら、B2B属性とエクスペリエンスイベントを持つ新しいマルチエンティティオーディエンスは、[ セグメントのセグメント ](../segmentation/methods/edge-segmentation.md#edge-segmentation-query-types) アプローチを使用して作成する必要があります。

>[!TIP]
>
>セグメントの&#x200B;**セグメント**&#x200B;は、1つ以上のバッチセグメントまたはエッジセグメントを含む任意のセグメント定義です。 **注意**: セグメントのセグメントを使用すると、プロファイルの失格は&#x200B;**24時間**&#x200B;ごとに発生します。

### B2B オーディエンスにおけるエンティティの解決と時間優先のマージ

アーキテクチャのアップグレードの一環として、Adobeではアカウントとオポチュニティのエンティティ解決を導入します。 エンティティの解決は、決定論的IDの照合と最新のデータにもとづいて行われます。 エンティティ解決ジョブは、B2B属性を持つマルチエンティティオーディエンスを評価する前に、バッチセグメント化の間、毎日実行されます。

>[!BEGINSHADEBOX]

#### エンティティ解決の仕組み？

* **前**: Data Universal Numbering System （DUNS）番号が追加IDとして使用され、アカウントのDUNS番号がCRMなどのソース システムで更新された場合、アカウント IDは古いDUNS番号と新しいDUNS番号の両方にリンクされます。
* **後**: DUNS番号が追加IDとして使用され、アカウントのDUNS番号がCRMなどのソースシステムで更新された場合、アカウント IDは新しいDUNS番号にのみリンクされるため、現在のアカウントの状態をより正確に反映できます。

>[!ENDSHADEBOX]

このアップグレードにより、次のことが可能になります。

* 日次エンティティ解決ジョブが完了したら、[!DNL Profile Access] APIを使用して最新の結合プロファイルを表示します。
* アカウントデータとオポチュニティデータの精度と一貫性を向上させ、セグメンテーション、アクティベーション、分析に活用します。

詳しくは、[[!DNL Profile Access] API](../profile/api/entities.md)を参照してください。

### マルチエンティティ B2B オーディエンスにおける結合ポリシーのサポート

B2B属性を持つマルチエンティティオーディエンスは、複数の結合ポリシーではなく、設定したデフォルトの結合ポリシーである1つの結合ポリシーをサポートするようになりました。

詳しくは、[Real-Time CDP B2B editionのセグメント化ユースケースガイド ](./segmentation/b2b.md)を参照してください。

### [!DNL Profile Access] APIでのB2B エンティティの検索と削除の廃止

[!DNL Profile Access] APIを使用するB2B エンティティの次の検索機能は非推奨（廃止予定）です。

* アカウントと人物の関係
* 商談と人物の関係
* Campaign
* キャンペーンメンバー
* マーケティングリスト
* マーケティングリストメンバー

[!DNL Profile Access] APIを使用した次のB2B エンティティの削除要求は非推奨（廃止予定）です。

* アカウント
* アカウントと人物の関係
* Opportunity
* 商談と人物の関係
* Campaign
* キャンペーンメンバー
* マーケティングリスト
* マーケティングリストメンバー

詳しくは、[[!DNL Profile Access] API](../profile/api/entities.md)を参照してください。

### セグメントジョブ APIの廃止

新しいアーキテクチャでは、「セグメントジョブの作成」エンドポイントと柔軟なオーディエンス評価はサポートされていません。

### アカウントと商談のプロファイル検索

アカウントスキーマと商談スキーマをルックアップディメンションエンティティとして取得できるようになりました。これは、毎日のエンティティ解決プロセスを完了した後にのみ行うことができます。 新しく取り込まれたレコードは、次のエンティティ解決サイクルが完了するまで（通常は24時間ごと）プロファイルのエンリッチメントまたはセグメント定義に使用できません。

### サンドボックスツールでのマルチエンティティオーディエンスのインポートの変更

アーキテクチャのアップグレードにより、これらのオーディエンスを含むパッケージがアップグレード前に公開された場合、B2B属性とエクスペリエンスイベントを持つマルチエンティティオーディエンスを読み込むことができなくなります。 これらのオーディエンスは読み込みに失敗し、新しいアーキテクチャに自動的に変換できません。 この制限を回避するには、更新されたオーディエンスを含む新しいパッケージを作成し、サンドボックスツールを使用してそれぞれのターゲットサンドボックスに読み込む必要があります。

開発サンドボックスは、新しいアーキテクチャにアップグレードされます。 自動更新できるオーディエンスはアップグレードされ、自動更新できないオーディエンスは無効になります。 無効なオーディエンスは、アップグレード後に再作成する必要があります。

詳しくは、[ サンドボックスツールガイド ](../sandboxes/ui/sandbox-tooling.md)を参照してください。
