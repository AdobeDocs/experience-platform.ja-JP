# 高度なデータライフサイクル管理のベストプラクティス

Advanced Data Lifecycle Management UIとData Hygiene APIを使用して、クリーンアップリクエストを効率的に管理し、Adobe Experience Platform サービスからデータを削除します。 リクエスト処理を合理化し、完了応答時間を最適化するために、次のベストプラクティスに従ってください。

## 前提条件 {#prerequisites}

このガイドでは、データライフサイクルワークスペースと[ データハイジーン API](./api/overview.md)について理解する必要があります。 このドキュメントを続ける前に、UI](./ui/dataset-expiration.md)またはAPIを使用して、[高度なデータライフサイクル管理](./home.md)および[ レコード削除要求の作成](./ui/record-delete.md)または[ データセット有効期限に関するガイドを確認してください。

## 作業指示の作成ガイドライン {#work-order-creation-guidelines}

Data Hygiene APIの`/workorder` エンドポイントを使用して、Experience Platformでレコード削除リクエストをプログラムで管理できます。 このエンドポイントを使用すると、削除リクエストを作成したり、ステータスを確認したり、既存のリクエストを更新したりできます。 APIを使用してこれらのアクションを実行する方法については、[作業指示エンドポイント ドキュメント ](./api/workorder.md)を参照してください。 レコードの削除要求は、処理が開始される前にバッチ処理され、完了するのに最大30日（標準のSLA）または15日（Privacy and Security ShieldまたはHealthcare Shield）かかる場合があります。 各ステージで起こることについて詳しくは、[削除タイムラインの記録](./home.md#record-delete-transparency)を参照してください。

>[!TIP]
>
>作業指示とは、効率的で体系的な処理を確実におこなうために、データのクリーンアップや変換などの特定のデータ管理操作を実行する構造化された要求です。

クリーンアップリクエストの送信を最適化するには、次のガイドラインに従います。

1. **リクエストごとにIDを最大化：** クリーンアップ リクエストごとに最大100,000個のIDを含めて、効率を高めます。 複数のIDを単一のリクエストにバッチ化することで、API呼び出しの頻度を減らし、単一のIDが過剰に要求されたためにパフォーマンス問題が発生するリスクを最小限に抑えることができます。 作業指示がバッチ化され、効率が向上するため、最大ID数のリクエストを送信して、より迅速な処理を実現します。
2. **個々のデータセットを指定：**&#x200B;効率を最大化するには、処理する個々のデータセットを指定します。
3. **API スロットリングに関する考慮事項：**&#x200B;遅いダウンを防ぐには、API スロットリングに注意してください。 より高い頻度でリクエストが小さい（100 ID未満）場合、429件の回答が返され、許容される割合で再提出が必要になる場合があります。

### 429 エラーの管理 {#manage-429-errors}

429 エラーが表示された場合は、指定された期間内に許可されたリクエスト数を超えたことを示します。 429件のエラーを効果的に管理するには、次のベストプラクティスに従ってください。

- **Retry-After ヘッダーを読み取る**: 429 エラーが返された場合は、「Retry-After」応答ヘッダーを確認してください。 このヘッダーは、リクエストを再試行する前に待機する時間を指定します。
- **再試行ロジックを実装**: &#39;Retry-After&#39;値を使用して、アプリケーションに再試行ロジックを実装します。再試行は、指定された時間が経過した後に試行され、その後の429 エラーが回避されるようにします。
- **リクエストをバッチ処理**：多数の小さいリクエストを連続して送信することを避けます。 代わりに、複数のIDを単一のリクエストにバッチ化して、コールの頻度を減らし、レート制限に達するリスクを最小限に抑えます。

## データセットの有効期限 {#dataset-expiration}

短期的なデータに対して自動データセットのクリーンアップを設定します。 Data Hygiene APIの`/ttl` エンドポイントを使用して、指定された日時に基づいてクリーンアップ用のデータセットの有効期限をスケジュールします。 データセットの有効期限を[作成する方法](./api/dataset-expiration.md)と[受け入れ可能なクエリパラメーター](./api/dataset-expiration.md#query-params)について詳しくは、データセットの有効期限エンドポイントガイドを参照してください。

## 作業指示とデータセットの有効期限ステータスの監視 {#monitor}

**I/O イベント**&#x200B;を使用して、データライフサイクル管理の進捗状況を効率的に監視できます。 I/O イベントは、Experience Platform内の様々なサービスの変更または更新に関するリアルタイム通知を受け取るための仕組みです。

I/O イベントアラートを設定されたWebhookに送信して、アクティビティモニタリングの自動化を有効にできます。 Webhook経由でアラートを受け取るには、Adobe Developer ConsoleでExperience Platform アラート用にWebhookを登録する必要があります。 詳しい手順については、[Adobe I/O イベント通知の購読](../observability/alerts/subscribe.md)に関するガイドを参照してください。

次のデータライフサイクルの方法とガイドラインを使用して、ジョブステータスを効果的に取得および監視します。

### I/O イベント {#io-events}

データライフサイクルタスクの進捗状況を効率的に監視するには、次の手順に従ってI/O イベントを設定して使用します。

- Webhookを設定して、ステータスの変更に関するプッシュ通知を受信します。
- 通知を使用して進捗状況を監視し、完了時に更新を受け取ります。
- API トラフィックを最小限に抑えるために、投票メカニズムを実装しない。

### 1つの作業指示に対する詳細な応答の取得 {#retrieve-detailed-work-order-response}

個々の作業指示の詳細については、次のアプローチを使用します。

- 応答データの詳細については、`/workorder/{work_order_id}` エンドポイントに対してGET リクエストを行います。
- 製品固有の反応と成功メッセージを取得する。
- この方法を通常のポーリングアクティビティに使用することは避けてください。

これらのベストプラクティスに従うことで、クリーンアップリクエストを効果的に管理し、高度なデータライフサイクル管理内で応答時間を最適化できます。
